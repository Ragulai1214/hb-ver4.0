# HEART BOX — プロトタイプ仕様書 v0.1

更新日：2026年11月13日  
開発目的：ゲームの基本的な駆け引きと面白さを検証する

## 1. ゲーム概要

### コンセプト

プレイヤーは自身のハートを、リブニーが振り下ろすハンマーから守る。

ハンマーが振り下ろされる回数は公開されるが、攻撃される順番は分からない。

プレイヤーは「何もしない」「シールド」「カウンターR」の3種類の行動から毎ターン1つを選択する。

限られたシールドを管理しながら、ハンマーの攻撃タイミングを予測し、カウンターを成功させてハンマーを破壊する。

### ゲームの特徴

- 攻撃タイミングの確率的な予測
    
- 限られた防御資源の管理
    
- カウンター成功による反撃
    
- ゴールデンハンマーによるハイリスク・ハイリターン
    
- リブニーの性格によって変化する攻撃傾向
    
- アイテムを利用した戦略
    

### 勝敗条件

**勝利：リブニーのハンマーのHPを0にする。**

**敗北：プレイヤーのHPが0になる。**

|対象|初期HP|
|---|---|
|プレイヤー|3|
|リブニーのハンマー|3|

HPはフェーズ終了後も引き継ぐ。

## 2. ゲームの進行

ゲームは複数のフェーズで構成される。

1. フェーズ開始
    
2. ターン数・攻撃回数を決定
    
3. 攻撃順序をランダムに配置
    
4. ゴールデンハンマーの使用有無と配置を決定
    
5. シールドとRを支給
    
6. アイテムを配布
    
7. プレイヤーが行動を選択
    
8. リブニーの攻撃を実行
    
9. 結果を公開
    
10. 次のターンへ
    
11. 全ターン終了で次フェーズへ
    

いずれかのHPが0になった場合は、即座にゲームを終了する。

### 2.1 フェーズ

1フェーズは複数のターンで構成される。

フェーズ開始時に以下を決定する。

- 総ターン数 `N`
    
- ハンマーの攻撃回数 `A`
    
- 攻撃ターンの配置
    
- ゴールデンハンマーの使用有無
    
- ゴールデンハンマーの使用位置
    

`N` と `A` はプレイヤーに公開する。

攻撃ターンの順番は非公開とする。

**未確定：** `N` と `A` の抽選範囲・分布。

プロトタイプでは仮設定を使用し、後から変更できるようにする。

### 2.2 攻撃ターン

ターンは2種類存在する。

|記号|内容|
|---|---|
|H|リブニーがハンマーを振り下ろす|
|E|リブニーがハンマーを振り下ろさない|

例：

```
総ターン数 N = 5
攻撃回数 A = 3

内部の攻撃順序：
H E H H E
```

攻撃順序はランダムに決定する。

プレイヤーには現在のターン以前の結果のみ公開する。

## 3. プレイヤーの行動

プレイヤーは毎ターン、以下の3つから1つを選択する。

### ① 何も置かない

防御も反撃も行わない。

- 攻撃ターン：プレイヤーが1ダメージ受ける
    
- 非攻撃ターン：何も起きない
    

シールドやRを消費しない。

### ② シールド

ハンマーの攻撃を防ぐ。

- 攻撃ターン：ダメージを受けない
    
- 非攻撃ターン：何も起きない
    
- どちらの場合もシールドを1個消費する
    

シールドの所持数が0の場合は選択不可。

### ③ カウンターR

ハンマーに対して反撃する。

- 通常攻撃ターン：ハンマーに1ダメージ
    
- ゴールデンハンマー攻撃ターン：ハンマーに2ダメージ
    
- 非攻撃ターン：反撃失敗、ダメージなし
    

攻撃に成功した場合、プレイヤーはダメージを受けない。

Rは成功・失敗に関係なく1個消費する。

Rの所持数が0の場合は選択不可。

### 3.1 行動結果一覧

|プレイヤーの行動|非攻撃|通常攻撃|ゴールデン攻撃|
|---|---|---|---|
|何も置かない|変化なし|プレイヤーHP −1|プレイヤーHP −2|
|シールド|シールド消費|ダメージ0|ダメージ0|
|R|R消費、反撃失敗|ハンマーHP −1|ハンマーHP −2|

※ゴールデンハンマーに対するシールドの挙動は、通常攻撃と同様に完全防御する仮仕様とする。

## 4. シールドとRの支給

### 4.1 シールド

1フェーズ開始時に以下の個数を支給する。

```
シールド数 = A - 1
```

例：

```
攻撃回数 A = 4
シールド数 = 3
```

シールドは使用すると消費される。

未使用分は次フェーズに持ち越せない。

### 4.2 カウンターR

各フェーズ開始時にRを1個支給する。

- 1回使用すると消費される
    
- 使用後は同じフェーズ内で再使用できない
    
- ただし、アイテム「リチャージ」によって補充可能
    
- 未使用分は次フェーズに持ち越せない
    

フェーズ開始時にはRの所持数を1にリセットする。

---

## 5. ゴールデンハンマー

### 5.1 基本効果

リブニーが使用する特殊なハンマー。

通常のハンマーより威力が高いが、カウンターされた場合の反動も大きい。

|結果|効果|
|---|---|
|プレイヤーに命中|プレイヤーHP −2|
|シールドに命中|ダメージ0|
|Rでカウンター|ハンマーHP −2|

### 5.2 使用制限

- 使用可能なフェーズでは最大1回
    
- 使用後は3フェーズのクールタイム
    
- 使用可能でも、必ず使うとは限らない
    
- フェーズ開始時に使用するかどうかを決定する
    

**未確定：** ゴールデンハンマーを使用するフェーズの選択条件。

### 5.3 情報公開

フェーズ開始時に、ゴールデンハンマーの使用有無をプレイヤーへ公開する。

ただし、**どの攻撃ターンで使用するかは非公開**。

例：

```
総ターン数：5
攻撃回数：3
ゴールデンハンマー：あり

プレイヤー表示：
? ? ? ? ?

内部データ：
G E H H E
```

`G` はゴールデンハンマー攻撃を意味する。

### 5.4 使用位置と性格

ゴールデンハンマーの使用位置は、リブニーの性格によって変化する。

まず攻撃順序を決定し、その中の攻撃ターン1つをゴールデンハンマーに変更する。

例：

```
攻撃順序：
H E H H E

攻撃ターンの位置：
1、3、4
```

**短気な性格**

最初の攻撃ターンを選びやすい。

```
G E H H E
```

**気長な性格**

最後の攻撃ターンを選びやすい。

```
H E H G E
```

性格によって使用位置の確率分布を変更する。

### 5.5 仮の性格別確率

攻撃回数が3回の場合の例。

|性格|最初の攻撃|中間の攻撃|最後の攻撃|
|---|---|---|---|
|短気|70%|20%|10%|
|標準|33%|34%|33%|
|気長|10%|20%|70%|

これらの数値は仮設定。

実装では性格別の確率を変更できるようにする。

リブニーはプレイヤーの当該ターンの行動を見て、ゴールデンハンマーの位置を変更しない。

## 6. アイテム

プロトタイプで使用するアイテムは3種類。

### 6.1 レントゲン

**効果：指定した未実行ターンが攻撃か非攻撃かを確認する。**

- 任意の未実行ターンを指定できる
    
- 通常攻撃とゴールデン攻撃は区別できない
    
- 使用時に1個消費
    
- 調査結果はフェーズ終了まで確認可能
    

### 6.2 回復

**効果：プレイヤーのHPを1回復する。**

- 最大HPは3
    
- HPが3の場合は使用不可
    
- 使用時に1個消費
    

### 6.3 リチャージ

**効果：カウンターRを1個補充する。**

- 使用済みのRを再使用可能にする
    
- 同じフェーズで複数回カウンター可能
    
- 使用時に1個消費
    

**仮仕様：** Rの現在所持数が0の場合のみ使用可能とする。

---

## 7. アイテム配布・所持ルール

|項目|内容|
|---|---|
|アイテム種類|3種類|
|配布タイミング|毎フェーズ開始時|
|配布数|2〜3個をランダム抽選|
|抽選方式|重複あり|
|所持上限|6個|
|持ち越し|可能|
|1ターンの使用回数|制限なし|
|使用タイミング|プレイヤーの行動確定前|

各アイテムの抽選確率は、初期プロトタイプでは等確率とする仮設定。

所持数が6個に達した場合、追加アイテムは受け取れない。

配布例：

```
フェーズ開始

配布数：3個

抽選結果：
レントゲン
レントゲン
リチャージ
```

アイテムは同じターンに複数使用できる。

例えば、レントゲンを2個使用してからRを選択することも可能。

## 8. プレイヤーが確認できる情報

### 常時表示

- プレイヤーの残りHP
    
- ハンマーの残りHP
    
- 現在のフェーズ
    
- 現在のターン
    
- フェーズの総ターン数
    
- フェーズの攻撃総数
    
- 残り攻撃回数
    
- シールド残数
    
- R残数
    
- 所持アイテム
    
- ゴールデンハンマーの使用有無
    
- ゴールデンハンマーのクールタイム
    

### ターン履歴

終了したターンについて以下を表示する。

- 攻撃／非攻撃
    
- 通常攻撃／ゴールデン攻撃
    
- プレイヤーが選んだ行動
    
- HPの増減
    
- 使用したアイテム
    

未実行ターンの攻撃内容は原則非公開。

ただし、レントゲンで確認した情報は表示する。

## 9. CPUの基本設計

プロトタイプでは複雑なAIを実装しない。

### CPUの処理

```
フェーズ開始
    ↓
攻撃ターンをランダム配置
    ↓
ゴールデンハンマー使用可否を確認
    ↓
使用する場合は性格に応じて配置
    ↓
攻撃順序を確定
    ↓
プレイヤーが各ターン行動
    ↓
決定済みの攻撃を実行
```

リブニーの性格はゴールデンハンマーの配置に反映する。

プロトタイプでは次の3種類を用意する。

- 短気
    
- 標準
    
- 気長
    

性格はゲーム開始時に決定し、ゲーム終了まで固定する仮仕様。

## 11. プロトタイプの検証目的

### 検証① カウンターの駆け引き

- Rをいつ使うか悩めるか
    
- 確定攻撃まで温存する戦略が強すぎないか
    
- カウンター成功時に達成感があるか
    

### 検証② シールドの資源管理

- 何もしない行動を選ぶ理由があるか
    
- シールドを浪費したときに適切な緊張感があるか
    
- 攻撃回数とシールド数の関係が適切か
    

### 検証③ ゴールデンハンマー

- 2ダメージのリスク・リターンが機能するか
    
- 性格による使用位置の違いを推測できるか
    
- 2ダメージカウンターが強すぎないか
    

### 検証④ アイテム

- レントゲンによってゲームが簡単になりすぎないか
    
- 回復によって敗北しにくくなりすぎないか
    
- リチャージによってRの希少性が失われないか
    
- 1ターン無制限使用が問題にならないか
    

### 検証⑤ ゲーム全体

- 1ゲームの平均所要時間
    
- プレイヤー勝率
    
- 平均フェーズ数
    
- ゴールデンハンマーへのカウンター成功率
    
- プレイヤーの行動選択割合
    
- アイテムの使用率

## 13. 実装方針

### 開発形式

HTML + CSS + JavaScriptによるブラウザプロトタイプを想定。

### 優先順位

**最優先：基本ゲームループ**

- フェーズ生成
    
- ターン生成
    
- 3つの行動
    
- HP管理
    
- 勝敗判定
    

**次：ゴールデンハンマー**

- 性格別配置
    
- 2倍ダメージ
    
- クールタイム
    

**次：アイテム**

- 3種類のアイテム
    
- ランダム配布
    
- 所持上限
    
- 使用処理
    

**最後：演出・デバッグ**

- ハンマー攻撃演出
    
- カウンター演出
    
- ゴールデンハンマー演出
    
- 履歴・確率表示
    
- デバッグモード
    

### 実装上の注意

ゲーム内部の攻撃順序は、プレイヤーの選択と独立して保持する。

ゴールデンハンマーの配置もフェーズ開始時に確定させる。

プレイヤーの行動を見て、攻撃内容を後から変更してはならない。

ゲームロジックとUI表示を分離し、ルールの変更を容易にする。
