# HEART BOX / Hammer Protocol — ver4.0

`docs/HEARTBOXver3.0.md`（2026-11-13）のハンマー戦を実装した独立プロトタイプです。仕様書のファイル名はver3.0ですが、今回の実装先はver4.0です。世界観は`docs/世界観・シナリオ.md`を参照し、地下施設の試験端末とリブニーの軽快・事務的な台詞で表現しています。

## 起動

このフォルダーの`index.html`をEdgeまたはChromeで開いてください。サーバー、ビルド、ネット接続は不要です。画像とsrcを含むフォルダーごと移動できます。ゲームを再読み込みすると進行はリセットされます。

## 操作

- 毎ターン「何も置かない」「シールド」「カウンターR」のいずれかを選択すると行動が確定します。
- 結果を確認し、「次のターンへ」を押します。フェーズ末では次フェーズへ進みます。
- レントゲンを押して任意の未実行ターンを指定できます。検査済みの同じターンへの重複消費は防止しています。
- 回復・リチャージはボタンで即使用。行動前なら同一ターンに複数個使えます。
- ハンマーHP0で勝利、あなたのHP0で敗北。終了後に再挑戦できます。
- 検証モードの設定適用は進行をリセットします。必要な記録はJSONで先に保存してください。

## 実装したルール

両者HP3。HPはフェーズ間で継続します。シールドは攻撃数−1、Rは1へ毎フェーズリセット。どちらも成功・空振りを問わず消費します。カウンター成功時はプレイヤー無傷でハンマーに通常1・金2ダメージです。

攻撃順序はフェーズ開始時にシャッフルして固定し、金の位置もその時点で確定します。プレイヤーの行動やアイテム使用による再抽選はありません。性格は開始時に決まり、ゲーム終了まで固定します。

アイテムはレントゲン・回復・リチャージ。初期設定では毎フェーズ2〜3個、各種等確率・重複ありで支給。合計6個を超えた分は受取不可、残りは持ち越し可能です。回復は+1（上限3では使用不可）。リチャージはRが0の場合のみ+1。レントゲンは通常・金を区別せず攻撃の有無のみを表示します。

通常UIは未実行ターンの実際の配置をDOMに入れません。検査結果と公開済みの履歴だけを表示します。全配置と性格は明示的に開いた検証パネルだけで確認できます。未来の配置は勝敗画面にも自動公開しません。

## 仮設定と未決定項目

以下は確定ルールではありません。検証パネルで変更できます。初期値は`src/game.js`の`H.defaults`に集約しています。

| 項目 | 仮設定 |
|---|---|
| 総ターン数N | 5〜7の整数を均等抽選 |
| 攻撃数A | 2〜4の整数を均等抽選（A≦N） |
| 金の使用率 | 使用可能フェーズごとに50% |
| 金の休止 | 実際に使用した後、次の3フェーズは使用不可 |
| 金へのシールド | 完全防御。検証用に無効化も可能 |
| 性格 | 短気・標準・気長から開始時に均等抽選 |
| 金の位置重み | 短気70/20/10、標準33/34/33、気長10/20/70 |
| アイテム | 毎フェーズ2〜3個、各種の重み1:1:1、合計上限6 |
| リチャージ上限 | R0のときのみ使用、所持R上限1 |

例えばフェーズ1で金を振った場合、フェーズ2・3・4を休止し、フェーズ5から再び抽選可能です。金の使用を予約しただけでは休止に入らず、実際の使用時に更新します。

攻撃回数が3以外の場合、各攻撃の順序を0〜1へ正規化し、先頭・中間・末尾の重みを線形補間してから総和で正規化します。攻撃1回ならその位置で確定です。性格は通常攻撃の配置には影響しません。この補間方法も仮仕様です。

設定では攻撃最大数≦最小ターン数を要求します。極端な値による表示・処理の負荷を避けるため、個数設定は最大30です。

## 確率表示

現在ターンが検査済みなら0%または100%。未検査の場合は以下です。

`（残り攻撃数 − 未実行の検査済み攻撃数）÷ 未実行かつ未検査のターン数`

金を通常攻撃と区別しない攻撃確率です。未来の検査も条件に含めます。結果画面では行動直前の確率を保持します。小数は整数%に丸めて表示します。

## 検証と記録

検証パネルで乱数シード・性格・ターン数・攻撃数・金の確率と休止・性格別重み・配布数とアイテム重みを変更できます。固定シードと同じ設定・操作で配置と配布を再現できます。

JSONには設定、開始・終了時刻、各フェーズの配置、各ターンの行動、HP変化、アイテム使用、行動直前の公開情報を含みます。ゲーム間の永続保存・累計統計画面は未実装です。ブラウザーを閉じる前にJSONを保存してください。

ゲームロジックは`src/game.js`、公開情報の描画は`src/ui.js`、操作処理は`src/main.js`に分離しています。ロジックはシード付き乱数・任意の乱数関数を注入できます。

開発検証（ゲーム起動時には不要）：親フォルダーで実行します。

```powershell
node --test ver4.0/tests/rules.test.js
npx playwright test --config ver4.0/playwright.config.js
```

Node標準テストで行動9通り、生成、資源、情報分離、アイテム、条件付き確率、金の休止、即時勝敗などを確認。ブラウザー検証には親プロジェクトのPlaywrightとインストール済みEdgeを利用します。直接HTMLを開き、勝利・敗北・再挑戦と390px幅での検査操作を確認します。
